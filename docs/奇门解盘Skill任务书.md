# 奇门遁甲解盘 Skill 任务书

## 1. 项目概述

- **项目名称：** 奇门遁甲解盘 Skill
- **目标形式：** 本地 Codex Skill，供用户以自然语言提交奇门盘面、起盘参数或具体问题后，获得结构化、可复核、克制的解盘分析。
- **首版定位：** 辅助传统术数学习与盘面整理，不替代医疗、法律、投资及其他专业判断，不自动宣称确定事实。
- **适用盘式：** 优先支持本项目生成的“拆补法时家转盘奇门”结果；对其他门派、飞盘或缺少规则说明的盘，先识别差异并提示不可直接混读。

## 2. 建设范围

### 2.1 首版功能

1. 读取本项目 JSON 盘面、命令行文本盘面和用户手工提供的九宫信息。
2. 识别公历时间、时区、地点、阴阳遁、元、局、旬首、旬空、马星、值符和值使。
3. 在用户未明确用神时，询问问题对象、我方、事项/对方和时间范围；不得擅自固定用神。
4. 按“问题定义 → 用神声明 → 宫位强弱 → 门星神干 → 生克关系 → 特殊标记 → 应期 → 建议”的顺序解盘。
5. 输出先给结论倾向，再给主要依据、相反依据、不确定性和可执行建议。
6. 明确区分排盘算法、常用解读框架与流派差异。
7. 识别并解释旬空、空亡、马星、值符、值使及中宫寄宫。
8. 对当前程序未自动计算的入墓、击刑、门迫、伏吟、反吟等标记，要求用户提供或明确标记为未核验。
9. 支持简版、标准版和教学版三种输出详细度。
10. 对医疗、法律、投资、安全等高风险问题附加适度的现实验证提示，不生成确定性决策指令。

### 2.2 首版不包含

- 自动起盘、改写现有排盘结果或擅自选择门派规则。
- 自动选用神后直接下断语。
- 大量古籍原文、未经核验的口诀汇编。
- 预测具体中奖、医疗结果、诉讼结果或投资收益。
- 把常见经验解释伪装成所有门派统一规则。

## 3. 核心解盘规则

### 3.1 规则优先级

1. 用户明确声明的门派、时间模式、换日法和中宫规则。
2. 盘面携带的 `rule_version`、`trace` 和配置字段。
3. 本项目默认 `chai_bu_v1.0.0`：拆补法、转盘、默认按时支取马星、中宫地盘干寄坤二、中宫仅显示天盘天干，九星/八门/八神留空，天禽随天芮。
4. 规则冲突时暂停断语，先列出冲突并请求确认。

### 3.2 用神原则

- 用神是解释选择，不是程序固定事实；首版 Skill 必须说明取法。
- 日干通常作为求测者/我方参考，时干作为事项、结果或对方参考，具体含义由问题语境决定。
- 财利常取生门，工作/职位常取开门，合作常参考六合，疾病常参考天芮与死门，出行常参考开门、马星、九天；均标注“常用取法”，允许用户改用其他门派口径。

### 3.3 读盘顺序

1. 把问题改写成可判断句，限定对象、结果和期限。
2. 预先声明用神及候选判据，避免看盘后挑选。
3. 比较我方宫、事项/对方宫及其门星神干。
4. 判断月令旺衰、宫与门星的生克、比和、受制和得助。
5. 查看值符主导性、值使事件渠道、旬空/空亡、马星和中宫寄宫。
6. 只在至少两个独立指标一致时给出倾向结论；保留相反证据。
7. 应期先给时间窗口，再说明冲空、填实、出空、冲合或马星等触发线索；不承诺精确日期。

## 4. 输入规范

支持以下输入：

```json
{
  "question": "三十天内能否签约？",
  "chart": {},
  "school": "拆补法时家转盘",
  "user_side": "日干",
  "subject_side": "时干",
  "time_range": "30天",
  "detail": "standard"
}
```

也支持只提供自然语言问题和盘面文本；缺少关键字段时，应列出缺口并只做有限分析。

## 5. 输出规范

标准输出必须包含：

1. **规则核对：** 时间、盘式、规则版本、用神取法。
2. **结论倾向：** 成/不成/有条件/信息不足之一，并使用概率式或倾向式语言。
3. **主要依据：** 我方宫、事项/对方宫、门星神干、生克、旺衰。
4. **特殊因素：** 旬空、马星、值符、值使、中宫寄宫；未计算标记明确写“未核验”。
5. **过程与应期：** 事件渠道、速度、变化和时间窗口。
6. **建议：** 只给与盘面依据对应的行动建议。
7. **边界说明：** 高风险问题需结合现实证据和专业意见。

简版控制在 5—8 句；标准版约 300—800 字；教学版可逐层解释，但不得复制整篇术语手册。

## 7. 触发条件与边界

### 7.1 应触发

- 用户要求解读奇门盘、分析九宫、判断某事成败或应期。
- 用户提供本项目起盘 JSON/文本并要求解释。
- 用户要求比较两个奇门盘的差异或复核解读过程。

### 7.2 不应触发

- 单纯要求计算干支、节气或生成九宫盘；交由起盘程序处理。
- 与奇门无关的一般占卜、八字或六爻问题。
- 要求把预测包装成确定事实或规避专业意见。

## 8. 验证与验收

### 8.1 行为测试

1. 提供完整 JSON 盘，能准确复述阴阳遁、元局、旬首、值符、值使、旬空和马星。
2. 中宫仅显示天盘天干；不会误报九星、八门、八神已落中宫。
3. 用户未给用神时会先询问或声明假设。
4. 对入墓、击刑、门迫、伏吟、反吟未提供数据时，不声称已计算。
5. 相同盘面和问题重复解读，规则核对与主要结论保持一致。
6. 医疗、法律、投资问题不会给出确定性替代专业意见。

### 8.2 质量验收

- 说明至少两条支持依据和一条反向或不确定因素。
- 所有门派差异均标为配置或常用取法。
- 输出简洁、可读、无无依据的吉凶断语。
- `scripts/quick_validate.py` 通过 Skill 结构校验。

## 9. 交付物与阶段

### 阶段一：任务书与规则边界

- 本任务书。
- 《奇门遁甲解盘攻略》作为参考底稿。
- 规则差异与当前程序能力清单。

### 阶段二：Skill 实现

- `SKILL.md`、`agents/openai.yaml` 和按需引用文档。
- 至少三组真实盘面行为测试。

### 阶段三：独立审查

- 用完整盘、缺字段盘、高风险问题进行独立前向测试。
- 根据结果修订触发描述、用神询问和边界提示。

### 阶段四：发布

- 通过 Skill 结构校验。
- 写明安装位置、调用方式和已知限制。

## 10. 已知限制

当前项目的部分起盘口径和解盘象义仍需更多古籍版本与独立人工案例校验。Skill 应诚实报告这一点，不能把代码实现或公开排盘仓库当作唯一权威。
