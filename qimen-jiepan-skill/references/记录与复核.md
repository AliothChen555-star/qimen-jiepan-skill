# 解盘记录与复核

记录工具只核结构、引用、方法、范围和条件状态之间的一致性，不替人取用、解盘、挑吉凶或推断日期。通过校验也不能证明背景属实、条文解释正确或预测有效。对用户的自然语言回答不要求固定标题和句式。

## 使用

先取得已冻结且通过完整校验的原盘，再初始化草稿：

```powershell
python -B scripts/reading_record.py init --chart chart.json --question "本次具体问题" --output reading.json
python -B scripts/reading_record.py validate reading.json --chart chart.json
```

初始化只建立 draft，不生成预测。输出文件已存在就报错，防止覆盖事前记录。人工完成各项后把 status 改成 final，再运行 validate。默认 final 校验拒绝空壳、草稿和未经登记的取用方法。程序只读给定原盘，不重排新盘；完整盘校验对冻结时刻作一致性复算。

真实结局放在另一个文件，引用 reading 文件的哈希和结果 ID，并分别记录观察日期、资料发布日期、真实事件日期及资料来源。不要回写事前已知事实、解释或预测来贴合结局。若原盘输入确有错误，保留原版，另存修订并解释原因。

## 字段与含义

- chart_ref 对完整原盘作排序键、紧凑 UTF-8 JSON 的 SHA-256，另存绝对时刻与排盘规则版本；不会因缩进或键顺序改变而失效。改变盘中任何内容都需要独立修订。
- method_profile.chart 保存原盘的时区、经纬度、时钟、换日、马星、拆补和寄宫配置；star_season 为 tongzong 或 yanyi_prose。final 的 method_id 必须在 assets/rules.json 的 methods 中，或显式登记 external_methods。
- known_facts 只收判断前已知背景，basis 固定 provided_before_reading。记录校验器无法判断自然语言事实是否真实，这部分须由问事记录和外部资料复核。
- roles 每项声明对象、符号种类 stem/door/star/spirit、实际值、heaven/earth/human/deity 层、宫号、main/hosted 主寄、primary 与取用来源。天盘中五展示干不能当独立落点；甲须先按具体甲柱解析成所取遁仪，再绑定实际盘符号。earth 星表示固定本宫星，天禽按坤二寄星处理。
- results 逐项固定 target、stage、success_criteria 与 horizon，state 为 assessed 或 undetermined；后者必须给 reason。工具保证声明的结果有各自结论，不能自动判断问句是否被充分拆分，这仍须审阅。
- evidence 指向一个 result_id、既有 role_ids、登记 source_id/rule_id；applicability 为字符串 true/false/unknown。polarity 相对该结果的成功标准：supports 为有利、opposes 为不利、neutral 为中性；critical 标记未知条件是否影响分项主判。fact 与 inference 分开，dedup_key 将同源或同一盘面事实标成一组。
- conclusions 每个分项恰一项。judgment 取 favorable/adverse/mixed/undetermined；support_ids 是支持该主判的证据，counter_ids 是反对主判的证据，excluded_ids 是未采用的证据。这三组不重叠，且合计覆盖该结果的全部证据。反向和排除证据逐项在 dispositions 中说明理由，另给 synthesis_reason 解释综合判断。不能把 false/unknown 当成立证据；关键 unknown 未解决时须未判并给原因。同 dedup_key 不能当多条独立支持或反向依据。
- imagery 只标 hypothesis 或 verified_context；假设须给 verification，已知背景须指向 known_fact_id，不得把后验结局伪装成已知背景。
- timing 可留空；若问及应期而尚无完整方法，可写 undetermined、空 windows 与原因。candidate 必须指向已启用 timing 方法，具有 exact_date_rule 和 event_scope，引用成立证据；一个 primary 主窗口与可选 alternative 窗口均在对应结果固定期限之内。目前内置首批事类没有启用精确日期规则，不能把日历填实/冲空列表直接登记为已支持应期。将来外部规则须完整登记来源、前提、例外和时法范围，不能只改状态假装已核实。

horizon 三种互斥形式：fixed 使用含时区的 start/end，区间结束晚于开始；current 使用 at，必须等于原盘绝对时刻，用于现状而非持续多久；unknown 使用 reason，表示题目要求的范围尚未确定或无法确定，该范围不能同时给确定方向的主判。结论 horizon 必须逐字段等于对应结果，防止把“趋势不利”偷换成“一个月内必败”。

external_sources 必须有唯一 ID、http(s) 正文 URL、location、scope；external_methods 必须关联来源并给 scope/limitations；external_rules 必须关联来源并列 scope、requirements、exceptions。登记只使出处可追查，不代表已经核实其正文或断法。不得覆盖内置 ID。来源文本与条件本身由规则审查流程负责。
