# 解盘流程

问题定义 → 预先声明用神 → 定我方/事项宫 → 看月令和五行生克 → 看门星神干 → 查值符值使、旬空、马星和中宫 → 给支持与反向依据 → 应期窗口 → 建议。

输出模板：规则；用神；结论；依据；特殊因素；应期；建议；不确定性。

## 最小完整流程

1. 按 SKILL.md 分流输入，取得程序的完整 JSON 或用户已有盘面；固定此次取时，不因对话继续就刷新盘。
2. 先声明“测什么、谁是本人、哪一个用神代表事项”。未指定圈子或期限就注明假设；现状问题不强制转换为成败预测。
3. 引用实际落宫，区分盘面字段、采用的传统象义和最终推测。例如“景门落某宫”为字段，“景门取名声”为取法，“可能更容易被注意”为推测，三者不能混成事实。
4. 给至少两条支持与一条反向依据或不确定性，不重复统计同一宫，也不编造反证。证据不足时降低结论强度。
5. 对空亡、马星说明它们影响哪个相关用神；无关宫的马星不用来凑应期。入墓、击刑、门迫、伏吟、反吟若未按明确规则逐项计算或人工复核，写“未核验”，不先暗用再补免责声明。
6. 现状问题不强定日期。未来事件只给有依据的窗口和触发线索；收窄窗口需要相互独立的相关线索，具体干支日换成公历日期时用历法程序核验。
7. 建议连接实际可做的事；不靠方位、摆件或符号化行动代替现实验证。传统解读不能证实他人的私下评价、意图或行为。

## 输出自查

- 时间来自实际 JSON 吗？规则版本和技能版本是否区分？地点是用户提供还是默认参数？
- 所有引用的门星神干都与本盘对应吗？中宫留空与寄干是否正确解释？
- 年命是否在解释落宫之前选定角色？有没有把年命当作起盘必需信息？
- 结论是否超出证据？有没有用单一凶神指控某人，或用泛泛的褒贬迎合用户？
- 若没有足够事件和期限信息，是否如实保留应期，而不是给出无依据的具体日期？
