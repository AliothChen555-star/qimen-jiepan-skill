# 评估方法与效验声明

维护时分别检查资料、程序、解盘行为和真实结果，按实际观测填写各项指标；无真实结局的准确率字段留空。此页用于维护评估，不要求在每次预测答复中复述。金融专项指标及执行入口见[金融数据与幅度](金融数据与幅度.md)。

## 四类证据分别保存

| 层面 | 检查什么 | 通过仍不能证明什么 |
|---|---|---|
| 资料与方法 | 原文位置、版本、适用事类、完整条件、限制和异说；规则卡是否忠于已核范围 | 该传统规则能预测现实事件 |
| 程序与数据 | 时间一致、排布几何、边界、字段、条件状态、源盘未改；合法输入接收，已知坏盘拒绝 | 引擎已经独立天文签核，或模型会正确解读 |
| 解盘行为 | 是否固定角色和方法、核条件与反证、分开状态/结果/应期、正确取象及留档 | 回答在真实世界会应验 |
| 真实预测与用途 | 事前固定的具体结果是否在期限内出现，是否优于适当基线 | 能保证下次正确，或可推广到未测的事类/人群/口径 |

资料签核逐条记录来源和核读范围；同一版本的多个转载不算独立证据。不同古籍口径先检查方法是否声明、是否混用，不能以“与另一表不同”直接判错。未核实条目保留未知，不当成成立。

程序测试保留合法例和反例，包含冻结盘元数据冲突、星干旋转脱耦、真实时区缺口/重复钟面、两套换日和显式取时。合成的18局×六十时柱检查是排布不变量检查，不是1080个已独立核实的真实日期盘。用同一历法提供者重算只能检验内部一致；独立完整签核盘和独立历表边界应另列来源与签核者。

## 程序与行为回放不能混记

`unittest` 的通过数须来自本次执行日志；不要沿用说明书中的旧数字。程序测试、规则卡字段检查和文件链接检查都不能记成一次模型解盘。

迁移开始时，原17个场景都应列为**待本版实际运行**。旧状态文件的预期更新、旧版0.4.0回放和一次书店开发试用不能替代本版17场景回放。后续状态以 `evals/replay-status.json` 和所链接的原始产物为准；没有产物的场景不能标通过。环境场景应真实执行相应入口或受控故障，并记录哪些宿主条件实际未测。

每次行为运行最少保存：场景ID、版本与输入、完整工具轨迹和实际回答、执行环境、评分项、评分理由、失败项和未测项。只审预期或在源文件里搜索措辞，标记为静态审阅，不算回放。

语义评分重点检查：

- 原盘、时间、盘法和对象绑定是否保持稳定；未知年命或同干同宫是否被补造。
- 每个问题结果是否有独立的期限、完成标准、支持/相反依据和条件状态。
- 条件未知是否被写成成立，几何匹配是否越权变成规则有效或现实结果。
- 取象是否由题义和盘面约束，是否把联想当成已发生事实。
- 期限内结果与精确应期是否分开；回答首句、正文、结尾是否对同一结果给出一致判断。
- 日历候选是否被冒充成事日期，现实价格或个人收益是否被传统吉凶直接代替。
- 事后信息是否另记，而非覆盖原预测、换用神或改动评分口径。

不以固定标题、逐字措辞或某一指定吉凶词作为主要通过标准。先核可确定字段，再核来源适用与推理一致；无法裁决的分歧单列，不强行给正确标签。

## 开发集、留出集与比较

已经被作者和改写者读过、用来修流程的原17场景及书店试用属于开发集。即使另一个执行者没见预期答案，这批题也不会因此重新变成未见留出题。

新建独立留出题，冻结题目、方法、评分表、模型、工具权限与运行预算后再测试。执行者不可见预期答案和未来结果；评分者尽可能不知道对应哪个版本。原版和候选版在相同输入下比较，事先固定重复次数，保留全部回答，不挑最好一次。

留出集被用于调试后应转为开发用途，后续另留新题。记录版本、模型和方法变化，不把多次调参中最好的一次包装成一次预定检验。行为改善可报告其具体范围，例如“角色改选次数减少”；不能把它改写为“现实命中率提高”。

## 真实前瞻记录

若要检验现实效验，先制定并保存前瞻计划，再观察结局。至少冻结：

1. 问题、当时已知事实和纳入条件；同一现实事件的多个追问如何归组。
2. 原盘及哈希方法、取时、方法配置、角色绑定、证据、规则条件和未判原因。
3. 每个具体结果的对象、方向/类别、期限、成功与失败标准；多个阶段分别登记。
4. 主要预测、主要时间窗口和附加窗口；概率只在实际事前给出且定义清楚时登记。
5. 技能/代码、规则卡、依赖、时区数据、模型与可获得的运行设置；无法获得的值明确标未知。
6. 事实来源、到期检查时间、缺失/争议结局处理、评分者和比较基线。

保存不可覆盖的原预测，后续事实和改正另附。若现实计划改变，也记录变化及预定处理规则；不能等看到结局再删去难判题、移动期限、改成另一阶段或扩大原时间窗口。用户反馈、公开事实和作者判断分开；有争议的标签保留争议。

同一问句有多个结果时，事先定义评分单位和主结果。例如“一个月谈定协议”与“半年有净收益”是两个结果，不可用后来一次联系或流水增长替代。资料缺失、未判和未到期均如实保留。

## 必须同时报告的分母

先列全部入组数、未到期数、已到期数、结局可判数、缺失/争议数。以下比例以**已到期且结局可判的全部结果数 K** 为共同总体：

| 量 | 定义 |
|---|---|
| `P` | K中按照事前标准给过明确、可评分预测的结果数 |
| `C` | P中预测正确的结果数；`0 ≤ C ≤ P ≤ K` |
| `C/P` | 已作明确预测中的正确比例 |
| `P/K` | 对全部可判结果的明确预测覆盖率 |
| `C/K` | 全部可判结果中得到正确明确预测的比例 |

三项同时报告，不能只报挑出的 `C/P`。`C/K = (C/P) × (P/K)`（分母非零时），用来显示正确预测与覆盖之间的关系；未判没有被冒充为错误，也没有从整体表现中消失。事前模糊到无法评分的回答按预定标准列为未判，不能事后挑一个解释算正确。

`P=0` 时 `C/P` 为不适用；`K=0` 时涉及K的比例为不适用，不写成0%或100%。同时报告原始计数、样本不确定性与所测范围。样本量按希望达到的精度、事件相关性和成本事前规划，不宣称某个固定数目自动足够。

若结果类别不均衡，除总体比例还看各类表现和混淆表，与多数类、状态不变等适合该问题的基线比较；不能以押中常见结果代替增量价值。概率预测若要评估，需事前给出概率并另用适当评分与校准；不从“偏强”“可能”事后编造数值。

## 应期与窗口宽度

应期评价先固定“什么阶段发生了什么”，再看事前主窗口是否覆盖该事件。全部主/辅窗口、触发种类、窗口长度和未命中都保留，不把任一消息落在任一宽窗内都算主预测成功。

至少报告观察期实际时长、主窗口时长、全部窗口并集时长、覆盖比例，以及与相同总宽度基线的比较。重叠区间只计算一次；多对象、多时点产生的多重尝试要披露。跨夏令时的“一天”采用事前所选的日历日或24小时语义，以 UTC 时长核对，不能事后挑更宽的算法。

`timing_candidates.py` 的 `coverage_fraction` 是支级候选宽度。它既不是事件发生概率，也不是应期命中率；一张盘覆盖观察期三分之一时间，不能凭某次碰中就声称三分之一或更高的预测准确率。

## 结论可说到哪里

每次发布分别列出：实际完成的资料核读、程序检查、行为回放与留出比较，以及是否已有真实前瞻结局。保留失败、未测和未解决限制。当前没有真实结局数据支持的准确率声明；不因重写、测试通过或表述更完整而承诺预测能力提高。

“内部一致”“条文忠实”“行为符合流程”“真实结果优于基线”是四种不同结论。只能报告已有证据支持的那一项及其范围。
