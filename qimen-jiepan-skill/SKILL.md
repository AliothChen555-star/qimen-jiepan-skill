# 奇门遁甲解盘

本 Skill 同时负责起盘和解盘。用户没有盘面不构成阻塞；先按下面的输入分流执行，再解释程序实际输出。

## 来源与输入分流

- 本技能标识为 `qimen-jiepan`。首次使用简短说明实际读取的技能路径；被问及来源时，区分文件路径、声明的上游仓库、已验证的 Git remote/commit。仅凭名称或 metadata 不能确认历史安装来源，也不能声称本地就是最新版。
- 用户明确指定仓库或技能路径时优先使用该版本。若本机还有 `qimen-dunjia` 等相似名称，先检查所选目录的 `SKILL.md`、`scripts/qimen_cli.py` 和 `scripts/qimen/`，不要把另一份技能缺少程序的结论套过来。远端网页缓存与 Git 内容不同时，以实际取得的文件为准并说明验证范围。
- 已给完整盘面：直接核对解读。缺项或图片不清：只补问影响判断的字段，不编造；中宫按规则留空不算缺项。
- 已给时间或要求“现在起盘”：直接调用内置程序，不再要求截图或重复确认起盘权限。只要求奇门测事、未给时间且未表示已有盘面时，说明“按本次运行时刻起盘”并使用 `--now`。
- 若用户表示稍后提供盘面、要求沿用前盘或不许重起，则遵从。仅询问理论或技能来源时不主动起盘；若是已有测事任务中的来源追问，先答来源，再继续原任务。
- 圈子、期限等信息不完整时，先声明最小假设继续；仅在对象或规则会实质改变且无法合理假设时询问。不要擅自把整体风评限定为职场，也不把未给期限改写成精确的未来天数。

## 起盘集成

- Skill 安装或更新后，先用系统 Python 运行 `python <Skill目录>/scripts/setup_env.py`。该脚本只在 Skill 目录内创建 `.venv` 并按 `requirements.txt` 安装依赖，不得向系统 Python 执行 `pip install`。
- `scripts/qimen_cli.py` 是统一入口：若 `.venv` 不存在或依赖版本已变，它会自动调用上述初始化逻辑，然后用 Skill 私有 Python 重新执行。
- 用户说“按当前时间起盘”或未提供时间但明确要求起盘：运行 `python <Skill目录>/scripts/qimen_cli.py chart --now --format json`。
- 用户提供 ISO 8601 时间：运行 `python <Skill目录>/scripts/qimen_cli.py chart --datetime <时间> --format json`。
- 用户提供经纬度、时区、真太阳时等选项时一并传递；不要同时传 `--now` 和 `--datetime`。
- 默认使用 `Asia/Shanghai` 标准时；有用户明确的时区则传入该时区。标准时无需追问城市，默认经纬度只是程序参数，不能当作用户所在地。真太阳时缺少经度时需补问，不能默用 120°。
- 起盘程序位于本 Skill 的 `scripts/qimen_cli.py` 和 `scripts/qimen/`，不依赖外部 qimen 项目；若虚拟环境创建或依赖安装失败，报告原始错误，不改用系统环境，也不自行编造盘面。
- 网络或权限受限时，按宿主的权限流程重试允许的初始化；不要据此断言技能没有起盘能力，也不要擅自安装第三方排盘器替代。完整性、安装及更新排障见 `references/起盘程序.md`。
- 起盘后保留完整 JSON 作为解盘输入，并在回答中列出取时瞬间、规则版本和时间模式。
- 同一问事沿用第一次成功起盘的 JSON。安装、解释来源或用户补充年命不构成重起理由；必要重放用已记录的时间传 `--datetime`。若先前已明确选定起局瞬间，即使尚未起盘也沿用该瞬间。用户明确要求重起时才换用新的 `--now`。不要提前把查看时钟的时间冒充程序实际取时。
- 用户只要求起盘时输出盘面，不强行进行吉凶解读；用户同时提出问题时，生成盘面后继续执行下方解盘流程。

## 工作流程

1. 核对时间、时区、地点、盘式、阴阳遁、元局、规则版本、旬首、旬空、马星、值符和值使。
2. 发现拆补/置闰、转盘/飞盘、换日或中宫规则冲突时先列冲突，不混用规则。
3. 将问题改成可判断句，区分现状判断与未来事件，注明对象、范围及已知期限。
4. 在解读落宫前声明用神及理由。程序不自动选用神，助手应按问题选择；用户授权自行取用时不把选择题退还用户。年命不是必填项，也不是独立起盘参数。日干与年命的主辅关系按事类预先说明，详见 `references/用神与象义.md`。
5. 按我方与事项/对方宫、旺衰生克、门星神干、值符值使、旬空马星、应期顺序分析。
6. 至少列两条支持依据和一条反向依据或不确定因素，再给倾向结论。每条写清“哪个用神、哪宫、何种组合或生克 → 支持什么判断”；同一组象的近义复述不算独立证据。证据不足时直说，不为凑数制造依据。
7. 应期只给窗口和触发线索；冲空、填实、出空、冲合或马星只有作用于用神、门或值使时才可引用。
8. 入墓、击刑、门迫、伏吟、反吟未提供或未计算时，明确写“未核验”。
9. 默认规则：拆补法时家转盘；马星按时支（horse.basis 可为日支）；中宫地盘干寄坤二；中宫只保留天盘天干，九星、八门、八神留空；天禽随天芮。
10. 医疗、法律、投资、安全问题只给倾向和核验建议，提醒结合专业意见与现实证据。
11. 风评、人际、感情中的他人想法只作象义推测，不将玄武、惊门等直接当成造谣、背叛或暗害的证据。不要用泛泛的“有能力但有距离感”代替推理；若盘面只能支持有限结论，就缩小结论。

## 输出

默认中文。标准版依次给出：规则核对与用神、结论倾向、主要依据、特殊因素、过程与应期、建议与不确定性。简版 5—8 句；标准版约 300—800 字；教学版按层解释。

默认只展示关键用神宫，用户要完整盘面时列九宫；完整 JSON 保留供复核。操作说明只写影响复现的时间、规则和来源，不把安装日志塞进解盘正文。现状问题可以写“本问不强定应期”；给日期窗口须有与用神相关的推算依据，并核验日历，不把建议观察一周包装成推算结果。末尾简短注明“奇门预测仅供学习研究参考，实际情况以现实反馈核验”。
