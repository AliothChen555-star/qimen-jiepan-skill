# 奇门遁甲解盘

本 Skill 同时负责起盘和解盘。用户没有盘面不构成阻塞；先按下面的输入分流执行，再解释程序实际输出。

## 来源与输入分流

- 本技能标识为 `qimen-jiepan`。首次使用简短说明实际读取的技能路径；被问及来源时，区分文件路径、声明的上游仓库、已验证的 Git remote/commit。仅凭名称或 metadata 不能确认历史安装来源，也不能声称本地就是最新版。
- 用户明确指定仓库或技能路径时优先使用该版本。若本机还有 `qimen-dunjia` 等相似名称，先检查所选目录的 `SKILL.md`、`scripts/qimen_cli.py` 和 `scripts/qimen/`，不要把另一份技能缺少程序的结论套过来。远端网页缓存与 Git 内容不同时，以实际取得的文件为准并说明验证范围。
- 已给完整盘面：直接核对解读。缺项或图片不清：只补问影响判断的字段，不编造；中宫按规则留空不算缺项。
- 已给时间或要求“现在起盘”：直接调用内置程序，不再要求截图或重复确认起盘权限。只要求奇门测事、未给时间且未表示已有盘面时，说明“按本次运行时刻起盘”并使用 `--now`。
- 若用户表示稍后提供盘面、要求沿用前盘或不许重起，则遵从。仅询问理论或技能来源时不主动起盘；若是已有测事任务中的来源追问，先答来源，再继续原任务。
- 圈子、期限等信息不完整时，先声明最小假设继续；仅在对象或规则会实质改变且无法合理假设时询问。不要擅自把整体风评限定为职场，也不把未给期限改写成精确的未来天数。

## 起盘集成

- Skill 安装或更新后，先用系统 Python 运行 `python <Skill目录>/scripts/setup_env.py`。该脚本只在 Skill 目录内创建 `.venv` 并按 `requirements.txt` 安装依赖，不得向系统 Python 执行 `pip install`。
- `scripts/qimen_cli.py` 是统一入口：若 `.venv` 不存在或依赖版本已变，它会自动调用上述初始化逻辑，然后用 Skill 私有 Python 重新执行。
- 用户说“按当前时间起盘”或未提供时间但明确要求起盘：运行 `python <Skill目录>/scripts/qimen_cli.py chart --now --format json`。
- 用户提供 ISO 8601 时间：运行 `python <Skill目录>/scripts/qimen_cli.py chart --datetime <时间> --format json`。
- 用户提供经纬度、时区、真太阳时等选项时一并传递；不要同时传 `--now` 和 `--datetime`。
- 默认使用 `Asia/Shanghai` 标准时；有用户明确的时区则传入该时区。标准时无需追问城市，默认经纬度只是程序参数，不能当作用户所在地。真太阳时缺少经度时需补问，不能默用 120°。
- 起盘程序位于本 Skill 的 `scripts/qimen_cli.py` 和 `scripts/qimen/`，不依赖外部 qimen 项目；若虚拟环境创建或依赖安装失败，报告原始错误，不改用系统环境，也不自行编造盘面。
- 网络或权限受限时，按宿主的权限流程重试允许的初始化；不要据此断言技能没有起盘能力，也不要擅自安装第三方排盘器替代。完整性、安装及更新排障见 `references/起盘程序.md`。
- 起盘后保留完整 JSON 作为解盘输入，并在回答中列出取时瞬间、规则版本和时间模式。
- 同一问事沿用第一次成功起盘的 JSON。安装、解释来源或用户补充年命不构成重起理由；必要重放用已记录的时间传 `--datetime`。若先前已明确选定起局瞬间，即使尚未起盘也沿用该瞬间。用户明确要求重起时才换用新的 `--now`。不要提前把查看时钟的时间冒充程序实际取时。
- 用户只要求起盘时输出盘面，不强行进行吉凶解读；用户同时提出问题时，生成盘面后继续执行下方解盘流程。

## 工作流程

先核对起盘字段与规则，定义问事对象、范围和期限；这只是准备，不提前取用或下最终断语。随后严格依次执行：**全盘分析 → 取用神 → 用神宫位关系 → 用神宫内四盘细析及宫内结论 → 合并分析 → 最终结论**。不得把旧版“用神—结论—补依据”流程套回来。

解盘前读取 `references/解盘流程.md` 和 `references/格局分析.md`；取用时读取 `references/用神与象义.md`。规则冲突按 `references/规则边界.md` 处理。每一步给出“本盘字段或组合 → 判定规则/取法 → 本步判断”，命名格局须列成立条件，不能只报吉凶标签。

1. **全盘分析。** 扫描外八宫及中宫寄宫信息，先看节令和气势分布、值符值使、星/门/奇仪各自的伏吟反吟、全盘格局、空亡与马星分布。给出全盘在动静、顺阻、显隐、主客上的背景判断及依据；不得把阴遁直接判凶、阳遁直接判吉，也不把某宫一项格局扩大为全盘结论。全盘扫描不等于逐宫长篇取象。
2. **取用神。** 在全盘判断之后，按问题声明本人、对方、事项及必要辅助用神，说明每个用神的取法、主辅、盘层与落宫。按事类取用，不能因刚看到某宫吉凶而换用神。年命不是必填项或独立起盘参数。
3. **用神宫位关系。** 先比较宫与宫：明确谁生谁、谁克谁、谁泄谁、比和、同宫、对宫，以及月令下各宫强弱。宫位生克与对宫关系分别解释；干合、门星相互作用若辅助比较，单列层次。此步先得出关系结构，宫内细节留待下一步。
4. **用神宫内四盘细析。** 对每个不重复的用神宫，依次分析天盘（九星、天盘奇仪）、地盘（宫卦五行、地盘奇仪及寄干）、人盘（八门）、神盘（八神）。必须分析天盘干加地盘干的有向格局、两层干各自的状态、星门与宫的生克、门迫/受制、刑墓、空马，以及满足条件的复合格局。天盘与地盘不能互换；同宫多个用神合并分析并分别说明角色。每宫最后合并为一条宫内结论：底层条件、表层走势、行动通道、助阻方式、成立或落空的条件。
5. **合并分析。** 明确引用各宫结论、第三步的宫位关系和第一步的全盘背景，解释它们如何共同作用；出现矛盾时说明是“关系相生但执行受阻”“局部可用但全局迟滞”等哪种结构。区分气势、意向、行动、结果，不能吉凶计票或重复累计同一组象。
6. **最终结论。** 直接回答所问的大势、主要走向、关键条件与可能取象；应期仅在问题需要且有用神相关依据时给出。每条结论可回溯到前面的证据，不在结尾突然增加未分析的格局。

内置 JSON 可用 `python <Skill目录>/scripts/inspect_patterns.py <盘面.json> --output <核验.json>` 核验格局。该工具读取已有盘面，输出分层伏吟反吟、逐宫干组合、生克、刑墓和复合格局等派生依据，不重起盘、不选用神、不自动断吉凶。外来盘面按相同规则人工核对；字段不足时只对相关判断标注“未核验”，其余部分继续。

## 输出

默认中文，先用一行注明取时、时间模式与排盘规则，再按六步顺序呈现。标准版以依据完整为准，不用旧版 300—800 字上限挤掉全盘或四盘分析。简版仍保留六步，每步至少一个依据；第四步可用紧凑表格，每宫保留四盘要点、格局和宫内结论。教学版展开成立条件与推导。

全盘分析展示总体结构与关键分布，详细四盘分析集中在用神宫；用户要完整盘面时列九宫。完整 JSON 保留供复核，不把安装日志塞进正文。

- 重点给奇门的大势和可能取象，使用“盘势偏向……”“可取……之象”“若……则……”等清楚的条件表达；不要把未获知的现实情节写成已发生的事实。
- 删除固定免责声明、逐段现实误差提醒、必列现实核验建议，以及机械的“两条支持加一条反向”配额。盘内存在冲突就解释冲突，没有则不为了平衡而编造反证。
- 风评、人际、感情可直接给象义判断，玄武、惊门等可取隐情、猜疑、口舌之象，但不能仅凭一象认定某人已经造谣、背叛或暗害。通过结论用语表达取象层次，不反复加提醒。
- 医疗、法律、投资、安全问题仍可分析盘势；仅当涉及具体高风险行动时加一句必要边界，例如不能凭盘停药或下重注，不延伸成常规提醒段落。
- 现状问题不强定应期。未来事件的出空、填实、冲合、马星等须作用于用神、相关门或值使；给公历日期须核验日历，不把任意观察天数写成推算应期。
