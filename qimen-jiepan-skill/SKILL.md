# 奇门遁甲解盘

负责起盘、核验与解读。保留完整原盘，以盘面字段和已声明规则解释所问。

## 输入与起盘

- 首次使用说明实际读取的技能路径。声明的上游仓库、实际 Git 版本和未知的安装历史分别报告。
- 用户指定版本或路径时使用该版本。相似名称不代表同一份技能；入口相对于实际 SKILL.md 定位。
- 已有完整盘面则直接核对。缺项只影响相关判断，不补造字段。
- 用户指定时间则用该时间。要求现在起盘，或明确测事且没有已有盘时，说明按本次运行时刻起盘并使用 `--now`。
- 同一问事沿用已选定时刻或第一次成功结果。补充年命、背景及来源追问不改变原盘。
- 理论咨询不主动起盘。只要求起盘时只展示盘面。

`scripts/qimen_cli.py` 是起盘入口。首次运行会通过 `setup_env.py` 创建技能私有 `.venv`。依赖只装在私有环境。安装、来源、重放及故障处理见 [起盘程序](references/起盘程序.md)。

```text
python <技能目录>/scripts/qimen_cli.py chart --now --format json
python <技能目录>/scripts/qimen_cli.py chart --datetime <带时区的ISO时间> --format json
```

默认 Asia/Shanghai 标准时。标准时无需城市；真太阳时须有用户认可的经度。保留 JSON，并注明取时、时间模式和规则版本。初始化失败时保留原始错误，不编造盘面。

## 解盘入口

先读取 [解盘流程](references/解盘流程.md)。准备阶段固定主体、问题目标、范围、期限及已知行动状态；此时不取用神。

正文依次为：**全盘分析 → 取用神 → 用神宫位关系 → 宫内四盘与格局 → 合并分析 → 最终结论**。

| 步骤 | 本步任务 | 需要读取的资料 |
|---|---|---|
| 全盘 | 提炼时令、符使、分层动静及关键格局分布 | [格局分析](references/格局分析.md) |
| 取用 | 按事类固定角色、主辅和落点 | [用神与象义](references/用神与象义.md) |
| 宫位关系 | 比较有向生克、强弱、同宫和对宫 | 解盘流程第三步 |
| 宫内 | 分析四盘、天地组合及发挥条件，每宫形成结论 | 格局分析；相关时读 [空墓与应期](references/空墓与应期.md) |
| 合并 | 用问题目标整合全盘、关系和宫内结论 | 解盘流程第五步 |
| 结论 | 回答大势、关键条件及相关取象 | 需要时间判断时读空墓与应期 |

主客法只在角色具有动静关系、方位占或用户指定方法时使用，另读 [主客取法](references/主客取法.md)。规则出处和采用状态见 [规则与出处](references/规则与出处.md)；不同盘式的支持范围见 [规则边界](references/规则边界.md)。

已有内置 JSON 可运行：

```text
python <技能目录>/scripts/inspect_patterns.py chart.json --output patterns.json
```

该工具只派生条件，不选用神、不重起盘、不判事件成败。九星可用 `--star-season yanyi_prose` 切换到《演义》正文口径；未指定时使用 `tongzong`。每层采用口径独立记录。

## 解释与表达

每步说明盘面依据、采用规则及本步判断。格局写成立条件；发挥情况接回事类和角色。

同宫角色共享一次宫内分析，再分别说明其作用。主干、寄干分明。星盘与奇仪盘随同一次转动形成的证据不重复累计。

用神宫内分析涵盖天盘星干、地盘宫干、人盘门、神盘神，以及天地叠加。每宫先得结论，再进入全盘整合。

默认中文。标准版以依据完整为准；简版可压缩文字和表格，仍保留六步及每宫结论。规则定义放在参考资料，正文只展开本问相关部分。

结尾给盘势、大势、关键条件和可能取象。未获知的现实情节用取象表达，不写成已经发生的事实。现状问题不强定应期。

不固定附免责声明、现实核验清单或正反证据配额。风评人际中的隐情、口舌等象义不单独证明他人已经背叛、造谣或暗害。具体医疗、法律、投资或安全行动涉及高风险时，保留一句必要边界。
